## Canonical authority and schema

- An authenticated server session resolves the stable `User.id`; client-provided `User.id`, OpenID, and UnionID are rejected as authority.
- `SweetCardClaim` is the one authoritative customer claim fact. The existing `SweetCardBinding` remains the only binding authority and now supports exactly one owner kind: Member or User.
- Test Candidate Migration 70, `20260906030000_sweet_card_claim_binding`, adds the claim table and the minimum additive User binding extension. It adds database uniqueness plus an XOR ownership check and performs no data rewrite.
- Claim and Binding use one database transaction and one account-scoped PostgreSQL advisory lock shared with Sweet Card administrative state and binding actions.
- Claim never activates a card, changes a balance, or writes Ledger, Redemption, Refund, Payment, or Order data.

## Binding mode contract

- `NONE`: creates the Claim view receipt and no Binding.
- `OPTIONAL`: creates the Claim; Binding is optional at claim time and may be completed later by the same claimant.
- `REQUIRED`: creates Claim and User Binding in the same transaction; either both commit or neither commits.
