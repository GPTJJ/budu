# G3 JSAPI transport and prepay coordination

Candidate application work only; production unchanged.

## Decisions and implementation

JSAPI API v3 is separate from existing POS MICROPAY v2. The HTTPS transport
signs exact method/path/body, pins the official hostname, bounds the entire
request to 10 seconds and 1 MB, aborts hanging streams and never retries itself.
All raw replies require platform signature verification before interpretation.

Quote freezes canonical WeChat identity ID, AppID and merchant ID. Prepay and
settlement validate that original identity, not mutable customer display data.
Prepay uses the immutable WX remainder, original merchant trade number and
expiry. Client parameters are signed only after rechecking PENDING state.
Every retry queries the original order first. Verified paid results use the
same PG finalizer and never create a second payment.

The **unreleased candidate migration** adds nullable `prepay_requested_at` to
the new online tender table; first-set time and prepay ID cannot be rewritten.
It commits before dispatch under the settlement lock. Cancellation can release
an entirely undispatched order locally; missing prepay ID alone is insufficient.
Attempted + ambiguous/not-found provider result retains CLOSING and its hold.
Provider close acceptance still requires a signed CLOSED query before release.
Recovery does not depend on the new-purchase rollout flag.

## Verification

Native PostgreSQL synthetic database was reset/reapplied through all 71 current
candidate migrations after this draft migration changed. No production data or
historical production migration was modified. Generated Prisma client updated.

Final combined suite: 90/90 PASS (75 native PG cases and 15 offline transport
cases), including the two reviewer-requested prepay races: concurrent prepares
and cancellation before delayed dispatch. Prepay suite: 10/10 PASS.
Includes prepay/cancel overlap, query-before-retry, stored prepay reuse,
ambiguous-attempt holds, undispatched cancellation, forged replies, and
immutable server amount/client signature checks. Build PASS.

Command: `SC11B_NATIVE_CONFIG=<private local config> SC11B_NATIVE_PG_MODULE=<local pg module> node --test --test-concurrency=1 scripts/test-online-schema-native.mjs scripts/test-online-outbox-native.mjs scripts/test-online-checkout-native.mjs scripts/test-online-payment-native.mjs scripts/test-online-prepay-native.mjs scripts/test-online-wechat-transport.mjs`.
Test files run sequentially because the outbox dispatcher consumes a shared
synthetic queue; concurrency cases within each file still use concurrent calls.

The undispatched-release premise requires all prepay writers to honor the PG
attempt marker. The corresponding MiniProgram candidate guards the reserved
`B[0-9a-f]{31}` merchant-number namespace and PostgreSQL-bound commerce orders
in legacy create, prepay, finalization, cancellation and refund entrypoints.
Parent rerun: 57/57 legacy tests PASS. At integration/cutover, precheck historical
namespace collisions and drain old cloud-function writers before enabling new
checkout; source tests do not establish current deployed writer isolation.
