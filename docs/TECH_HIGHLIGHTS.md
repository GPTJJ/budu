## 亮点一：微信支付 V2 付款码（MICROPAY）全链路自研

**背景**：门店收银需支持顾客出示付款码收款。难点不在"调通接口"，而在**扣款结果不可信**：网络超时、响应丢失、系统异常时，无法确定是否已扣款，误判失败会导致重复扣款或漏单。

**方案与工程要点**：
- **安全层**：HMAC-SHA256/MD5 签名、严格扁平 XML 解析器（拒绝 DOCTYPE/实体/属性/嵌套/畸形 CDATA，1MB 上限，全覆盖消费校验）、响应字段交叉校验（金额/商户号/订单号/签名）
- **状态机**：SUCCESS→成功；USERPAYING/SYSTEMERROR/网络歧义→**待核对**（绝不直接判失败）；明确终态错误→失败；金额不一致→人工核对；`recall=Y` 按官方协议持续撤销重试
- **崩溃恢复**：网络请求发出前原子落库「已发起」标记（含核对队列标志），进程崩溃后由后台核对器按 orderquery 恢复，绝不盲查本地未发起的支付
- **跨进程对账**：数据库原子条件更新租约（owner/until），多实例只允许一个执行者；正常完成即按所有者身份释放租约；进程死亡靠租约过期回收
- **稳定性**：撤销时限以稳定基准（首笔请求时间）推导，反复查询不推迟；nextActionAt 排期门控真实节奏
- **硬性时限**：单次操作 90s 绝对墙钟上限（覆盖 DNS/TCP/TLS/请求/响应/主备域名/全部顺序子调用），到期主动 abort 底层请求并返回受控歧义结果
- **fail-closed 配置**：密钥 32 位校验、X.509 有效期与公私钥匹配、终端公网 IPv4 严格校验；任一不满足即通道关闭
- **安全红线**：付款码零持久化、零日志；服务端按订单门店强制灰度

**结果**：支付、对账、撤销全链路自动化测试覆盖（真实栈 + 假网络传输），含崩溃窗口、双进程竞态、绝对时限中止等场景。

## 亮点二：数据迁移工程（KV → PostgreSQL，跨机房迁移）

**背景**：系统早期以 JSON 文档 + KV 存储运行，存在整体读写、无事务、无约束、并发覆盖风险；且需从香港机房迁回北京生产。

**方案与工程要点**：
- **存储层重写**：JSON/KV → PostgreSQL + Prisma（52 张表、外键约束、索引、事务）
- **迁移机制**：Prisma 迁移链（27+ 个增量迁移）、一次性可弃用 schema 验证、`db push` 结构同步
- **跨机房迁移**：完整数据导出/导入、**运行时契约核验**（容器参数、网络、secrets、capabilities 逐项对照）、只读 smoke、回滚预案（旧容器/旧镜像保留）、nginx 流量切换
- **幂等与可验证**：迁移后业务行数核对、外键目录级证明（RESTRICT 约束）、失败自动回滚

**结果**：迁移全程可回滚、可复现、有证据留存；生产切换后健康检查与业务接口验证通过。

## 亮点三：多端 POS 与三端响应式

**背景**：同一收银系统需跑在桌面、iPad（横屏专用布局）、手机三种形态，且收银场景对"断网/刷新不丢单"敏感。

**方案与工程要点**：
- 三端响应式布局（≥1024 / iPad 横屏 1024×768 / ≤767 触屏），iPad 横屏左订单右商品双栏
- 收银核心：商品目录（分类/SKU/条码）、购物车（数量/删除/赠送/折扣/备注）、礼盒搭配面板、现金当面确认
- 会话韧性：购物车与订单状态跨刷新恢复（sessionStorage 按门店隔离）、未完成订单不残留
- 扫码：付款码/商品条码识别、同码防重复提交、摄像头权限/后台释放处理
- 回归保障：Playwright iPad 仿真浏览器套件（16+ 场景）+ 手机端场景

## 亮点四：通知中心 + 企业微信自建应用集成

**背景**：工资条、审批、调货等业务通知需触达员工个人微信，且通道未配置时不能影响业务。

**方案与工程要点**：
- 统一通知入口：业务只调 `notify()`，站内消息 + 通道派发解耦
- 双通道：企业微信自建应用（textcard 卡片，点击直达） / 公众号模板消息，企微优先
- 绑定：扫码授权（qrConnect/网页授权）+ **管理员手动绑定企微 userid 兜底**
- 可靠性：access_token 缓存复用、失效自动重取重发一次、投递记录审计（sent/skipped/failed + 通道错误码）
- 企微接收消息验签：SHA1 签名 + AES-256-CBC 解密（43 位 EncodingAESKey 校验）端到端验证

## 亮点五：工程质量体系

- **统一测试矩阵**：27 套单元测试 + 9 套浏览器 E2E，统一入口调度，**环境隔离**（生产密钥/数据库凭证自动剥离，fail-safe）
- **支付域测试深度**：固定签名向量、严格 XML 夹具清单、真实栈 E2E（仅伪造网络传输）、真实 PostgreSQL 一次性 schema 验收、数据库不可用即 fail-closed
- **CI 质量门禁**：构建 + 测试 + 校验 + diff 检查，失败阻止部署
- **部署**：Docker Compose + Nginx HTTPS + 健康检查 + 自动回滚
