# BUDU 门店运营管理系统 需求说明书

> 版本：v1.0　日期：2026-08-23
> 用途：第三方询价 / 交付验收 / 系统资产文档化
> 说明：本说明书基于**已在生产环境运行**的 BUDU 系统（buducandy.cn）整理，功能描述以现行系统行为为准，可直接作为询价与验收依据。

## 1. 项目概述

### 1.1 背景与目标
为连锁烘焙/甜品零售企业提供**多门店一体化运营管理**：门店收银（POS）、员工与排班、工资条发放与签收、库存与调货、发票、审批、资产、经营分析与业绩日结。系统面向 6 类角色（开发者/管理员/财务/店长/员工/收银），支持桌面、iPad、手机三端使用，并集成企业微信/公众号个人通知。

### 1.2 用户角色
| 角色 | 权限要点 |
|---|---|
| developer（开发者） | 全部模块；账号管理、二级密码、系统设置 |
| admin（管理员） | 与开发者同权（除账号安全外） |
| finance（财务） | 全量查看；工资条、业绩、审批 |
| manager（店长） | 本门店经营数据、审批、业绩录入 |
| staff（员工） | 本人工资条签收、排班查看 |
| cashier（收银） | 仅 POS 点单 |

### 1.3 整体架构
- 前端：React 18 + Vite + Tailwind，三端响应式（桌面 ≥1024 / iPad / 手机 ≤767）
- 后端：Node.js + Express，REST API（`/api/v2/*`）
- 数据：PostgreSQL + Prisma（52 张表）；历史数据自 KV 迁移而来
- 部署：Docker Compose + Nginx + HTTPS，CI 自动构建部署，支持回滚

## 2. 功能需求

### 2.1 账号与权限
- 登录/登出（scrypt 密码哈希 + HttpOnly Cookie + JWT）、当前用户会话
- 6 角色 × 模块级权限矩阵（模块：首页/分析/雇员/工资条/门店业绩/排班/邮寄/POS/商品/库存/发票/资产/审批/设置）
- 账号管理（开发者）：创建、禁用、角色、门店绑定、员工绑定（staffKey）、权限复核
- 二级密码：删除雇员等高风险操作二次确认
- 审计：关键操作留痕（用户迁移盘点、审批日志、资产操作日志、工资条签收记录）

### 2.2 门店管理
- 多门店维护（名称、key、排序）、账号-门店授权（storeKeys）
- 门店数据源：手动/系统录入模式切换
- 门店业绩录入（多周期：日/周/月/自定起止）、日结汇总与审计

### 2.3 POS 点单（桌面 / iPad / 手机）
- 商品目录（分类、SKU、条码、价格、上下架）、搜索/扫码加购
- 购物车：数量、删除、清空、**赠送（赠品行）**、**折扣（1–10 折）**、备注
- **Balls 礼盒**：SKU 前缀识别 + 4 口味自由搭配面板
- 结算：创建订单（幂等 checkoutKey）、应付计算（含折扣、赠送不计费）
- 支付渠道：现金（当面确认）、微信扫码（付款码）、支付宝（预留）、模拟支付（测试环境）
- **微信付款码支付**：仅 live 模式开放；付款码 18 位校验；支付中自动轮询核对，防重复扣款
- 支付状态机：created/pending/success/failed/closed/timeout/refunded；订单状态机：draft→pending_payment→paid→completed / failed / closed / cancelled / refunded
- 会话恢复：未完成订单、成功订单跨刷新恢复；购物车本地持久化（按门店隔离）
- 订单记录：查询、筛选、删除保护（有支付记录/已完成订单不可删）、取消保护（未决微信支付不可取消）
- 支付查询/关闭（撤销）接口

### 2.4 订单与日结
- 订单汇总（按门店/周期）、当日订单默认查询
- 业绩日结：门店每日录入、自动汇总、审计留痕、调薪联动（每日工资调整）

### 2.5 员工与排班
- 员工主档（门店绑定、姓名、岗位、电话）、账号绑定（staffKey）
- 排班（按门店/周期）、每日到店人员
- 员工离职/移除（二级密码保护）

### 2.6 工资条
- 工资周期：月度 / 周度 / 自定起止日期
- 发放：按员工批量创建工资条（总额、明细快照、图片附件）、Excel 导入
- 签收：员工查看并签收（确认留痕、通知发放人）、开发者代签
- 图片附件完整展示（无高度限制卡片）
- 通知：发放 → 员工微信/站内提醒；签收 → 发放人提醒

### 2.7 审批中心
- 审批模板（自定义表单）、提交人-审批人-抄送人流程
- 审批状态机（待审/通过/驳回）、多节点、图片附件预览
- 通知：待办、结果、抄送三态推送

### 2.8 库存管理
- 商品/SKU 档案（进价、售价、安全库存、单位）、条码
- 库存预警（低于安全库存高优先级提醒）
- 调货（跨门店申请/发货）、采购申请、报废、盘点
- 库存流水（StockLedger）、余额（StockBalance）

### 2.9 发票管理
- 发票抬头/税号/金额录入，**图片 OCR 自动识别**（腾讯云 OCR；未配置时手动填写）
- 发票台账与统计

### 2.10 资产中心
- 资产档案（文件、类型、到期日）、分类、证件到期提醒、操作日志、访问授权

### 2.11 门店邮寄
- 邮寄发件单（方式、收件人）、记录查询

### 2.12 经营分析（首页/看板）
- 今日经营：营业收入、订单数、客单价、优惠金额、商品销量、本月累计
- 营业趋势（按日/周/月）、环比上月同日
- 待办：待审批、库存预警、异常事项、门店待录入

### 2.13 通知中心（站内 + 微信）
- 统一通知入口（站内消息：未读/已读/签收状态）
- 消息模板（内置 12+ 模板：工资条/审批/调货/采购/发票/邮寄/库存/资产）
- **微信个人提醒**：企业微信自建应用（textcard 卡片）或公众号模板消息
- 绑定：员工扫码授权一次（qrConnect/网页授权）；**管理员手动绑定企微 userid（兜底）**
- 投递审计：每消息记录 inapp/wechat 投递状态（sent/skipped/failed + 通道错误码）
- 测试推送接口

### 2.14 支付（微信支付 V2 付款码 MICROPAY）
- 付款码支付（`/pay/micropay`）、订单查询（`/pay/orderquery`）、撤销（`/secapi/pay/reverse`，双向 TLS）
- 安全：HMAC-SHA256/MD5 签名、严格 XML 解析（防 XXE/畸形 CDATA）、字段交叉校验（金额/商户号/订单号）
- 状态处理：USERPAYING/网络歧义 → 待核对（绝不直接判失败）；明确终态错误 → failed；recall=Y → 撤销重试
- **后台自动对账**：崩溃恢复（网络发起标记）、稳定撤销时限（以请求时间为基准）、跨进程租约（多实例不重复查询）、nextActionAt 排期门控、绝对时限中止（90s）
- 灰度：按门店白名单（ENABLED_STORES）；未授权门店拒绝
- 退款：本阶段明确返回未开放（501）
- 配置 fail-closed：APIv2 密钥 32 位、证书有效期+公私钥匹配、终端公网 IPv4；未配置 = 通道关闭

### 2.15 系统设置
- 门店维护、数据源切换、修改密码/二级密码、微信提醒绑定/解绑/测试、账号管理入口

## 3. 非功能需求

| 项 | 要求 |
|---|---|
| 安全 | 密码 scrypt 哈希；HttpOnly Cookie；敏感字段（付款码/密钥/证书）零持久化零日志；fail-closed 配置 |
| 合规 | 微信支付 V2 官方签名/撤销协议；付款码不落库；审计留痕 |
| 可用性 | Docker 化部署、健康检查、CI 自动部署与回滚、nginx HTTPS |
| 数据 | PostgreSQL 52 表；迁移机制（Prisma）；一次性 schema 验证迁移；备份 |
| 兼容 | 桌面 / iPad（Safari）/ 手机（触屏）；微信/企微内可访问 |
| 通知 | 通道未配置/未绑定自动降级为仅站内，不影响业务 |

## 4. 验收要点（每模块抽查）
1. POS：三端完整下单 → 现金/模拟支付 → 成功页 → 刷新恢复会话；赠送/折扣金额正确
2. 微信支付：付款码支付全链路状态转换；对账恢复；撤销；灰度门店 403
3. 工资条：发放 → 员工签收 → 发放人通知；Excel 导入
4. 审批：提交 → 审批 → 抄送 → 通知
5. 库存：预警/调货/采购状态流转
6. 通知：绑定 → 测试推送 → 站内+微信双通道；未绑定 skipped 记录
7. 权限：6 角色访问矩阵逐项核对
8. 自动化：全部单元测试 + 浏览器回归通过（CI 门禁）

## 5. 询价与交付说明
- 本系统为**已运行、可演示**的生产系统，询价时可按"功能还原 + 数据迁移 + 支付合规"三部分拆分报价
- 数据归属、源码归属、微信商户号资质归属为合同必列条款
- 验收以本说明书 §4 抽查项 + 自动化测试结果为准
